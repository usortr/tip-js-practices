## 4. Модель данных и функции

**Модель задачи:** объект с полями id (безопасное целое число > 0), title (строка 1-100 символов после trim), completed (boolean), priority ("low" | "medium" | "high").
**Распределение ответственности:** data.js хранит константы, task-service.js содержит чистые функции с валидацией и возвратом новых структур, main.js управляет сценарием и выводом.

**Почему id не равен индексу:** id — это постоянный уникальный идентификатор сущности, который не меняется при добавлении или удалении других задач. Индекс — это временная позиция элемента в массиве, которая сдвигается при мутациях массива. 
**Почему getTaskStats возвращает число, а не строку с процентом:** Для соблюдения разделения ответственности. Функция расчёта должна возвращать сырые данные (число), а форматирование (добавление % и округление через .toFixed()) — это задача уровня представления (UI/терминала в main.js).
**Какие объекты копируются при изменении задачи:** Создаётся новый массив и новый объект только для изменяемой задачи (с использованием spread-синтаксиса). Все остальные неизменённые задачи переносятся в новый массив по ссылке (без глубокого копирования), что экономит память.

## 9. Вывод

По сравнению с ПР1, где данные хранились в отдельных переменных, в ПР2 логика инкапсулирована в функции, работающие с массивом объектов. Это позволило масштабировать код. Активное использование return вместо console.log внутри функций обеспечило возможность переиспользования логики. Неизменность данных гарантируется созданием новых массивов и объектов через spread-синтаксис, что было проверено сравнением ссылок и контролем длины исходных массивов в сценарии. Основной сложностью было отслеживание порядка свойств при spread-копировании объектов, что было решено строгим размещением изменяемых полей после ...task.
